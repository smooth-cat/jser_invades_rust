一、VecDeque<T> 的本质

VecDeque<T> 是基于可增长环形缓冲区的双端队列。它和 Vec<T> 一样把元素存在堆上，但通过 head 把“逻辑上的第 0 个元素”与“物理上的第 0 个槽位”解耦。

// 标准库实现的概念化形式，字段是私有的 pub struct VecDeque<T, A: Allocator = Global> { head: WrappedIndex, // 逻辑首元素的物理槽位，透明包装 usize len: usize, // 已初始化的元素数 buf: RawVec<T, A>, // 持有 ptr + cap + allocator } // 默认 Global 分配器是 ZST，概念上就是 4 个 usize // 64 位平台: 8 + 8 + 8 + 8 = 32 bytes

注意：VecDeque 使用 Rust 默认布局，字段顺序和 ABI 都不是稳定承诺。下图用语义字段解释原理，不应当作 FFI 布局依据。对 T 为 ZST（如 ()）的情况，元素不占字节，也不需要真实的堆分配。

二、栈与环形堆缓冲区

当前 Rust 1.97.1 中，From<[T; N]> 内部先为 N 个元素请求容量，再用 ptr::copy_nonoverlapping 整块转移数组，最后设置 head = 0 和 len = N。具体容量与内部字段仍属于实现细节。

环绕函数：把堆块外的索引映射回内部

当 head 前移或 tail 越过堆块边界时，索引会短暂落到 [-cap, 0) 或 [cap, 2cap) 区间。环绕函数负责把它们折回 [0, cap)，避免写出模运算的分支差异：

// i 是包裹后的逻辑索引，cap 是堆块容量 fn surround(i: i32, cap: i32) -> i32 { // [-cap, 0) → 加 cap 回到正区间 if i < 0 { return i + cap; } // [0, cap) 直接存 if i < cap { return i; } // [cap, 2cap) → 减 cap 环绕回开头 i - cap } // cap = 6 时：surround(-1, 6) = 5，surround(6, 6) = 0

三、逻辑索引如何映射到物理内存

// i 是用户看到的逻辑索引，要先保证 i < len physical_index = (head + i) % cap // pop_front() + push_back(40) 后: head = 1, cap = 3 q[0] → slot[(1 + 0) % 3] → slot[1] → 20 q[1] → slot[(1 + 1) % 3] → slot[2] → 30 q[2] → slot[(1 + 2) % 3] → slot[0] → 40

as_slices()：一个逻辑序列，最多两段物理切片

A
第一段从 head 向堆块末尾延伸：&[20, 30]
B
如果发生环绕，第二段从物理槽位 0 开始：&[40]
→
迭代顺序永远是 A 后接 B，所以用户看到 [20, 30, 40]

VecDeque 不能总是直接当作一个 &[T]；跨尾部时必须使用 as_slices() 获取两段，或先调用 make_contiguous() 重排为一段。

四、双端增删

push_front(x)
head = (head - 1) mod cap

先把 head 向前环绕一格，再在新 head 写入 x，len += 1。

push_back(x)
tail = (head + len) mod cap

在 tail 写入 x，然后 len += 1。head 保持不变。

pop_front()
read(head); head = (head + 1) mod cap

读出队首，head 向后一格，len -= 1。不会自动缩容。

pop_back()
len -= 1; read((head + len) mod cap)

先缩短逻辑长度，再从原队尾槽位读出元素。

为什么两端都是 O(1)
1
元素不需要像 Vec::insert(0, x) 那样整段后移。
2
队首改变只更新 head；队尾位置由 head + len 计算。
3
只有 len == cap 的 push 才需扩容，因此 push 是均摊 O(1)。

五、中间插入、删除与连续化

insert(i, x) 会选较短的一侧搬移

Vec 中间插入只能移动后缀；VecDeque 可以在前缀和后缀中选较短的一边，将空洞从最近的端点搬到插入位置。

front i 个元素 ← 选更小一侧 → len - i 个元素 back

搬移量约为 min(i, len - i)，时间复杂度仍是 O(n)，但通常比固定搬后缀更少。remove(i) 也使用同样的就近搬移思路来填补空洞。

六、扩容时发生什么

当 len == cap 时，下一次 push_front 或 push_back 必须让 RawVec 增长。扩容后物理边界变了，实现会搬移环绕数据的一部分，以保持逻辑顺序。

1
请求更大的堆分配，新 cap 至少满足所需长度。
2
如果数据原本跨越旧容量的边界，搬移较合适的那一段，使新边界下的环顺序正确。
3
更新 ptr / cap / 必要时的 head，再写入新元素。

扩容可能改变堆地址，也可能搬动环内元素，因此之前取得的引用不能跨过这次可变操作存活。

增长因子、首次非零容量以及具体搬移策略是标准库实现细节，不应依赖“永远恰好翻倍”。上方操作台为便于观察，在满容时使用翻倍并线性化的等价模拟。

缩容与清空

q.clear(); // Drop 所有元素，len = 0，cap 通常保留 q.truncate(n); // Drop 逻辑区间 [n, len)，cap 不变 q.shrink_to_fit(); // 请求将容量缩到尽量接近 len，可能重分配

七、索引、迭代与原地修改

let x = q[2]; // 边界检查 + 环形索引计算 + 读取 q[2] = 99; // 在对应物理槽位原地写入 for value in &q { // 逻辑顺序: 先迭代 A，再迭代 B use_value(value); } let contiguous: &mut [i32] = q.make_contiguous(); contiguous.sort(); // 需要一个连续切片的算法

单次索引是 O(1)，但与 Vec 相比多了环形映射。如果热路径算法强依赖连续切片，应直接使用 Vec，或在合适的边界上显式调用 make_contiguous()。

八、内存生命周期：Drop

1
按逻辑元素区间遍历已初始化槽位，对每个 T 执行 Drop。
2
RawVec 释放容量对应的整个堆分配；未初始化槽位不会被当作 T 执行 Drop。
3
栈帧回收 head、len 和 RawVec 的小型控制结构。

对 i32 这类无 Drop 副作用的类型，元素 Drop 会被优化掉。对 String 等类型，先释放每个元素自己持有的资源，再释放 VecDeque 的槽位堆块。

九、操作复杂度速查

操作时间复杂度可能重分配内存动作
push_front / push_back均摊 O(1)满容时可能更新 head 或 tail 槽位；必要时增长
pop_front / pop_backO(1)否ptr::read + 更新 head / len
get(i) / q[i]O(1)否边界检查 + 环形物理寻址
insert(i, x)O(min(i, len-i))满容时可能向较近端点搬移元素
remove(i)O(min(i, len-i))否向较近端点填补空洞
as_slices()O(1)否借用一段或两段连续内存
make_contiguous()O(n)否在已有分配内重排元素
clear / truncateO(k)否Drop k 个被移除元素，cap 保留
shrink_to_fitO(n)可能缩小堆分配并保留逻辑顺序
