一、先看结论

enum Drink2 {
  Coffee(String),
  Cola,
  Water { boiled: bool },
}
let coffee = Drink2::Coffee(String::from("拿铁"));
let cola = Drink2::Cola;
let water = Drink2::Water { boiled: true };
// 作用域结束：先 drop(water)，再 drop(cola)，最后 drop(coffee)

枚举 Drink232 B：载荷 24 B + tag 1 B + 填充 7 B
判别值 tag1 B，记录当前是哪个变体
Coffee 载荷String 头部 24 B 整体内嵌，不再为枚举值堆分配
Cola / Water载荷 0 / 1 B，与 Coffee 共用同一块联合体空间
堆上数据只有 "拿铁" 的 6 B UTF-8 字节在堆上
Rust 的 enum 是 "tag + union"，不是 JS 的对象多态。 TypeScript 的联合类型只存在于类型层；Rust 的每个 Drink2 变量都占一整块 32 B 槽位，通过 tag 决定如何解释槽里的字节。Cola 再“轻”，栈上也照样占满 32 B。

String 对缓冲区的所有权 已释放 / 已失效
图里的地址、tag 数值与容量用于解释布局，不是 ABI 保证。 Rust 没有承诺判别值放在载荷之后、也没有承诺具体数值；String 的字段顺序同样未被稳定承诺。编译器优化后，布局可能不同。

三、每一层实际放了什么

位置 / 类型64 位示意大小存放内容说明
枚举 Drink232 B载荷联合体 + 判别值 + 对齐填充大小由最大变体决定；每个变量都占满整块槽位
判别值 tag1 B变体编号（示意 Cola=0 · Coffee=1 · Water=2）实际数值与存放位置由编译器决定
Coffee 载荷24 BString { ptr, len, cap } 头部头部内嵌在枚举槽里，不额外堆分配
Cola 载荷0 B—与最大变体共用空间，不占额外字节
Water 载荷1 Bboiled: bool = true位于载荷开头，其余 23 B 闲置
堆：UTF-8 缓冲区请求 6 B“拿铁”的 6 个 UTF-8 字节（E6 8B BF E9 93 81）由 coffee 的 String 拥有，随其析构而释放

为什么 tag 单独占了 1 B

String 是 ptr / len / cap 三个 usize，头部里没有多余的空位可以藏判别值；而 3 个变体需要区分 3 种状态，所以 tag 只能独立占 1 B，再补 7 B 填充凑成 8 B 对齐的 32 B。

为什么 Cola / Water 也占 32 B

栈上的枚举变量按最大变体预留空间。Cola 再“轻”也得占满整个槽位——这正是 enum 与“指针多态”的本质区别：数据就在槽里，不需要解引用。

四、作用域结束时的析构顺序

drop(water)后声明的局部变量先析构
drop(cola)无载荷，立即结束
drop(coffee)析构内嵌的 String 头部
free("拿铁")释放 6 B UTF-8 缓冲
槽位回归栈上 3 × 32 B 归还
这里只有 coffee 拥有堆内存，cola 和 water 的析构不涉及 free。 若在作用域结束前用 match coffee 消费掉它（源码里正是如此），析构链会提前截断，只剩 water 与 cola 收尾。
