Box<Dog>：从装箱到自动释放

src/ptr_01_box.rs · box_01_basic · 64 位平台概念布局

一、先看结论

let dog = Box::new(Dog {
  name: "旺财".to_string(),
});
println!("{} 叫: {}", dog.name(), dog.bark());
let inner: Dog = *dog;
println!("解引用后 name = {}", inner.name);
let mut dog2 = Box::new(Dog {
  name: "大黄".to_string(),
});
dog2.name = "二黄".to_string();
// 作用域结束：先 drop(dog2)，再 drop(inner)
三层所有权
栈上 Box8 B，只保存指向 Dog 的指针
堆上 Dog24 B，此处就是一个 String 头部
String 头部ptr + len + capacity，各 8 B
UTF-8 数据另一次堆分配；两个汉字是 6 B
*dog搬出 Dog，并回收 Box 的 Dog 分配块
Box<Dog> 不是“所有内容只分配一次”。 Box::new 为 Dog 分配一块堆内存；Dog 里的 String 又拥有自己的 UTF-8 缓冲区，所以本例的每个装箱 Dog 通常涉及两块独立的堆分配。

三、每一层实际放了什么

位置 / 类型64 位示意大小存放内容所有权变化
栈：Box<Dog>8 B指向堆上 Dog 的唯一非空指针Box 被 drop 时递归 drop Dog，并回收 Dog 分配块
堆：Dog24 B本例只有 name: String，所以就是 String 头部*dog 把这 24 B 的值逻辑搬到栈上的 inner
String 头部24 B缓冲区指针、字节长度、容量移动 String 只搬头部，不复制 UTF-8 字节
堆：UTF-8 缓冲区请求 6 B“旺财”“大黄”或“二黄”的 6 个 UTF-8 字节随拥有它的 String 析构而释放
&Dog 临时借用8 B 概念指针name() / bark() 调用期间的共享引用不转移所有权，也不新建堆分配

为什么 *dog 之后缓冲区没动

let inner: Dog = *dog 搬的是 Dog 值，也就是 24 B String 头部。头部中的 ptr 仍指向原来的“旺财”缓冲区，所以字符数据不用复制，Box 的 Dog 分配块则可立即回收。

为什么字段赋值先释放“大黄”

右侧先构造新的“二黄” String，然后替换 dog2.name。旧字段值不再有所有者，会当场 drop 并释放“大黄”缓冲区；Dog 的 24 B Box 分配块本身保持不动。

四、作用域结束时的析构顺序

drop(dog2)后声明的局部变量先析构
drop(Dog)递归析构 name: String
free("二黄")释放当前 String 缓冲区
free(Box block)回收 dog2 的 24 B Dog 分配
drop(inner)最后释放“旺财”缓冲区
原来的 dog 已在 *dog 时被消费，不会在函数末尾再次 drop。它原先拥有的 Dog 分配块已回收，而 String 的所有权已经随 Dog 搬到 inner。
