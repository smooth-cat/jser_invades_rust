三、闭包在栈上究竟存了什么

概念上的结构体

// 编译器生成的匿名类型（伪代码）
struct Readonly<'a> {
  n: &'a i32,
}

let readonly = Readonly { n: &n };

// Fn 调用不需要修改闭包对象
Fn::call(&readonly, ());

为什么是 Fn

  • 捕获时：只创建 &n，没有修改或移走 n。
  • 调用时：Fn::call 只需要 &self，同一个闭包可重复调用。
  • 复制时：捕获字段 &i32 是 Copy，因此该闭包值也可 Copy。
  • 生命期：readonly 不能比被借用的 n 活得更久。

五、几个容易混淆的边界

println! 把字符串放到堆上吗？

这段代码不会构造 String。格式字面量在 .rodata，format_args! 生成的参数视图是临时值，通常在栈或寄存器中。标准输出设施可有进程级内部状态，但它不是 readonly 闭包所有的堆数据。

指针和被指向的值都在栈上？

对，本例是栈指向栈。readonly.n 是一个存在栈上的引用值，它指向同一个 demo 栈帧里的 n。引用并不等于“指向堆”，它可以指向栈、堆或静态区。
