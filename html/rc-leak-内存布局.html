一、先看结论

struct Node {
  age: i32,
  next: RefCell<Option<Rc<Node>>>,
}

let a = Rc::new(Node { age: 18, next: RefCell::new(None) });
let b = Rc::new(Node { age: 20, next: RefCell::new(None) });

*a.next.borrow_mut() = Some(Rc::clone(&b));
*b.next.borrow_mut() = Some(Rc::clone(&a));

let b_from_a = a.next.borrow();
println!("a.next 指向的年龄: {}", b_from_a.as_ref().unwrap().age);
println!("a 强计数 = {}, b 强计数 = {}",
  Rc::strong_count(&a), Rc::strong_count(&b));

三、每一层实际放了什么

位置 / 类型64 位示意大小存放内容是否影响计数
栈：Rc<Node>8 B指向 RcBox<Node> 的非空指针每个活着的 Rc 对应 strong +1
栈：Weak<Node>8 B指向同一 RcBox 的指针，不保证 Node 存活显式 weak +1，strong 不变
栈：Ref<'_, T>通常 16 B指向 T 的指针 + 指向借用标志的守卫只改 RefCell 借用标志，不改 Rc 计数
堆：RcBox<Node>约 40 Bstrong 8 B + weak 8 B + Node 24 B计数单元本身就在此分配块内
堆：Node24 Bage: i32 4 B + 对齐填充 4 B + RefCell<Option<Rc<Node>>> 16 Bnext 内的 Some(Rc) 使目标 strong +1
堆：FixedNode40 Bage 与对齐填充共 8 B + next/prev 两个 RefCell，各 16 Bnext 计 strong；prev 只计 weak

RefCell 内部

RefCell<Option<Rc<Node>>> 中有一个 8 B 的借用标志和一个 8 B 的 Option<Rc<Node>>。Option 利用非空指针的空值优化，所以 Some(Rc) 不需要额外的判别字节。

RcBox 内部

Rc 的数据不是只有 Node。一次堆分配同时包含 strong 计数、weak 计数和 value。strong 归零时先 drop value；等 weak 也归零后，整块 RcBox 内存才被回收。

表中大小是常见 64 位目标上、使用默认 Global 分配器时的概念布局。Rust 没有把 Rc、Weak、Ref 的 ABI 和字段顺序稳定为语言保证，实际以当前目标和标准库实现为准。

四、为什么 Weak 能让析构继续传导

drop(b)B.strong：2 → 1
drop(a)A.strong：1 → 0
drop(A.value)A.next 使 B.strong：1 → 0
drop(B.value)B.prev 的 Weak 被析构
deallocate两块 RcBox 都回收
struct FixedNode {
  age: i32,
  next: RefCell<Option<Rc<FixedNode>>>,
  prev: RefCell<Option<Weak<FixedNode>>>,
}

*a.next.borrow_mut() = Some(Rc::clone(&b)); // B.strong + 1
*b.prev.borrow_mut() = Some(Rc::downgrade(&a)); // A.weak + 1
Weak::upgrade() 是唯一个需要的生存检查。 A 还活着时，b.prev.borrow().as_ref().and_then(Weak::upgrade) 返回 Some(Rc<A>) 并临时使 A.strong +1；A.value 已经析构后则返回 None，不会产生悬垂引用。
