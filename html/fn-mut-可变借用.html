一、先看结论

let mut value = String::from("js");

let mutable = || {
  value.push_str(" is good");
};

run_mut(mutable);
println!("value：{value}");

fn run_mut(mut f: impl FnMut()) {
  f()
}
mutable 的本体

调用接收者FnMut::call_mut(&mut self, ())
Trait 层级实现 FnMut / FnOnce，不实现 Fn
闭包不直接保存堆指针。 它保存的是指向整个 String 头部的 &mut String。闭包调用 push_str 时，才经由这个独占引用修改头部的 ptr / len / cap 并写入堆缓冲区。

三、两层指针，三个不同对象

概念上的闭包结构体

// 编译器生成的匿名类型（伪代码）
struct Mutable<'a> {
  value: &'a mut String,
}

let mutable = Mutable {
  value: &mut value,
};

FnMut::call_mut(&mut mutable, ());

指针链路

  • mutable：栈上 8 B，只有一个 &mut String 字段。
  • value：栈上 24 B，是 ptr + len + cap 头部。
  • UTF-8 字节：在堆上，由 value 拥有并在 drop 时释放。
  • 关键区别：闭包借用的是 String 对象，不是单独借用某个堆字节。

四、MIR 证据：为什么是 FnMut

// run_mut(f)

_4 = copy ((*_1).0: &mut String);

&mut value创建独占借用捕获
move mutable → f闭包值移入 run_mut
call_mut(&mut f)可修改闭包所捕获的状态
push_str(f.value)更新头部并写入堆缓冲区

五、借用规则与返回后状态

独占借用存活时

创建 mutable 后，value 处于独占借用中。在借用结束前，外部代码不能再直接读或写 value；对它的修改必须经由闭包中的那一个 &mut String。

run_mut 返回后

f 被 drop，独占借用结束，因此下一行 println!("value：{value}") 又能借用 value。此时它的内容已是 "js is good"；堆缓冲区仍由 value 拥有，不会随闭包返回而释放。
