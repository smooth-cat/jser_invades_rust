为什么 node2 会留下“空壳”

drop(node2) 后 node2.strong 到 0，其 RefCell<Node> value 立即析构。但 node3.borrow().prev 还保存一个 Weak，所以存放 strong/weak 的 RcBox 头仍在。upgrade() 只读 strong=0 就返回 None，不会访问已析构的 value。

遍历中的瞬时计数

正向遍历中，node_rc 使当前节点 strong 临时 +1，node_rc.borrow() 又使同一分配中的 borrow flag 临时变为 1。反向 Weak::upgrade 成功时产生临时 Rc，但不改变 weak 计数。

大小与字段是常见 64 位目标、默认 Global 分配器下的概念图。repr(Rust) 的字段顺序与 Rc / Weak ABI 都不是语言稳定保证，实际结果以当前目标和标准库实现为准。

四、drop 之后的精确传导顺序

drop(node1)N1.strong：1 → 0
drop(N1 RefCell<Node>)N1.next 使 N2.strong：2 → 1
drop(node2)N2.strong：1 → 0，value 析构
drop(N2.next)N3.strong：2 → 1
upgrade(N3.prev)读到 N2.strong=0，返回 None
drop(node3)释放 N2 空壳、N3 value 与 RcBox
Weak 打破的不是“指针可达性”，而是 strong 所有权环。 1 → 2 → 3 的 next 是单向强所有链，反向 prev 只提供可检查的导航。因此从头部 drop 时，strong 能顺着 next 一直传导到 0。
