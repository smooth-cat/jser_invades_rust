一、Vec<T> 的本质

Vec<T> 是 Rust 标准库中最常用的堆分配容器。它在栈上只占 24 字节（64 位平台），真正的数据全部在堆上。

// 标准库中的定义 (简化)
pub struct Vec<T, A: Allocator = Global> {
    buf: RawVec<T, A>,   // 管理堆内存: ptr + cap
    len: usize,              // 已使用的元素个数
}

pub struct RawVec<T, A> {
    ptr: Unique<T>, // 非空指针 (NonNull + 所有权标记)
    cap: usize,       // 已分配的容量 (元素个数)
    alloc: A,         // 分配器 (默认 Global, 零大小)
}

Global 分配器是 ZST（零大小类型），编译器会优化掉，所以 Vec<T> 实际就是 3 个 usize = 24 字节。

// ─── 各初始化方式的 cap 来源 ───

// 1. Vec::new() → cap = 0, 不 alloc
let v: Vec<i32> = Vec::new(); // ptr=dangling, cap=0, len=0

// 2. vec![a, b, c] → cap = 元素个数 (编译期已知)
let v = vec![10, 20, 30]; // cap=3, len=3

// 3. vec![0; n] → cap = n
let v = vec![0; 1024]; // cap=1024, len=1024, 一次 alloc(4096B)

// 4. Vec::with_capacity(n) → cap = n
let v: Vec<i32> = Vec::with_capacity(8); // cap=8, len=0, alloc(32B)

// 5. iter.collect() → cap = size_hint().0 (下界)
let v: Vec<_> = (0..100).collect();
// Range 的 size_hint = (100, Some(100))
// → with_capacity(100), 一次搞定

let v: Vec<_> = some_iter
    .filter(|x| x > &5)
    .collect();
// Filter 的 size_hint = (0, upper)
// → 下界=0, 从 cap=0 开始逐步扩容!

collect() 的 size_hint 机制

1
collect() 内部调用 iter.size_hint() 获取 (lower: usize, upper: Option<usize>)
2
用 lower 作为初始 cap 调用 Vec::with_capacity(lower)
3
若 upper == Some(n) 且 n == lower（精确长度，如 Range、slice::iter），一次分配到位
4
若 lower = 0（如 filter、flat_map），退化为从 cap=0 开始，每次 push 触发倍增扩容
5
若 upper 存在但 > lower，仍只分配 lower（保守策略，避免浪费）
初始化方式初始 cap首次 push 是否 alloc适用场景
Vec::new()0是 (cap 0→1)不确定大小，延迟分配
vec![a, b, c]元素个数是 (cap==len 时)编译期已知少量元素
vec![0; n]n—（已满）需要 n 个相同初始值
with_capacity(n)n否 (前 n 次)预知大致大小，减少 realloc
collect() (精确迭代器)exact len否Range、slice 等
collect() (filter 等)0是无法预知输出长度

💡 性能建议: 如果你知道大致元素数量（比如从文件读 10000 行），用 Vec::with_capacity(10000) 可避免约 14 次 realloc（log₂(10000) ≈ 13.3）。每次 realloc 都是一次 memcpy + alloc + dealloc。

// 标准库源码 (alloc/src/raw_vec.rs, 简化):
fn grow_amortized(&mut self, len: usize, additional: usize) {
    // 新容量 = max(cap * 2, len + additional, 1)
    let new_cap = if self.cap == 0 {
        max(1, len + additional)       // 首次: 至少 1
    } else {
        max(self.cap * 2, len + additional) // 倍增，但不低于所需
    };
    // 然后 realloc 到 new_cap * size_of::<T>() 字节
}
// 注意: 对于 T 为 ZST (如 Vec<()>)，永远不 alloc，cap = usize::MAX

3.1 push — 尾部追加

4.4 truncate / clear

T
truncate(n): 对 [n..len) 中每个元素调用 ptr::drop_in_place，然后 len = n。cap 不变。
C
clear() = truncate(0)：Drop 所有元素，len 归零，堆内存仍保留。

对 i32 等 Copy 类型，drop_in_place 是 no-op，编译器会优化掉整个循环。

七、操作复杂度速查

操作 时间复杂度 是否可能 realloc 底层关键调用
push (有空位) O(1) 否 ptr::write
push (扩容) O(n) 均摊 O(1) 是 (×2) realloc + memcpy
pop O(1) 否 ptr::read
insert(i, x) O(n) 可能 memmove + ptr::write
remove(i) O(n) 否 ptr::read + memmove
swap_remove(i) O(1) 否 ptr::read + ptr::copy(1)

truncate / clear O(n) 否 drop_in_place × n
shrink_to_fit O(n) 是 (缩小) realloc + memcpy
