  s.push_str(" world!"); // 这里的 String 操作不是本图重点

把“栈内存变化”说准确

语义层面：s1、s、s2 是三个不同时刻的绑定名；owner 沿着 s1 → s → s2 传递，任意时刻都只有一个合法 owner。
栈槽层面：在这张可观察的教学图里，ptr / len / cap 三个字段从 &s1 所在的 caller 栈槽进入 &s 所在的 callee 栈槽——这就是“栈上的 String 结构发生了移动”。实现可能用寄存器传递、复用栈槽，或把这次传递优化掉，因此不应把它理解成必然执行一次 memcpy。
旧栈槽层面：move 之后，s1 的旧槽可以被覆盖、复用，甚至暂时保留原来的位模式；这些位不代表 s1 仍然可用。编译器只保证：代码不能再通过 s1 访问这份资源。

本例：move

  • 堆上仍然是一块 H0。
  • 所有权从旧绑定转给新绑定。
  • 旧绑定不可再用，避免双重释放。

如果写成 clone

  • 会得到一份独立的新值/新资源。
  • 原绑定和新绑定都继续有效。
  • 这是显式复制成本，不是本例的默认行为。

最后的清理时刻

回到 demo 后，println! 只借用 s2 读取它。函数末尾，s2 是仍然存活的唯一 owner，于是由它负责释放 H0；s1 和已经销毁的参数 s 都不会再释放一次。
