三、String::from("hello") 发生了什么

let s = String::from("hello");
1

编译器在 .rodata 段放入字节 [0x68, 0x65, 0x6c, 0x6c, 0x6f]

字面量 "hello" 的类型是 &'static str，即指向 .rodata 的胖指针

2

String::from 为 5 个字节申请容量；分配器可能在内部取整分配块，但 String::capacity() 仍记录可用容量

→ 通过 GlobalAlloc::alloc(layout) 向操作系统申请堆内存

→ 底层是 mmap（大块）或 brk/sbrk（小块，由 allocator 如 jemalloc 管理）

3

ptr::copy_nonoverlapping(src, dst, 5) —— 从 .rodata 拷贝 5 字节到堆

设置 len = 5, cap = 5（本例中）

4

栈上得到 24 字节的 String 值，指向堆上的新副本

.rodata 中的原始字面量依然存在，但 String 不再引用它

如果替换内容比原范围短（如 "Rust" 4B < "world" 5B），内部先做 replace_range 删除多余部分再插入； 如果更长，则可能触发 realloc。整个过程是 delete_range + insert_str 的组合。

七、操作复杂度总览

操作 时间复杂度 是否可能 realloc 核心动作
push / push_str O(1) 均摊 cap 不足时是 copy 到 ptr+len
insert(idx, ch) O(n) cap 不足时是 memmove 后移 + 写入
remove(idx) O(n) 否 memmove 前移 + len--
truncate / clear O(1) 否 仅改 len
replace_range O(n) 新内容更长时可能 delete + insert 组合
shrink_to_fit O(n) 是（缩小） realloc 到 len 大小

八、Drop —— 生命周期结束

// 当 s 离开作用域：
impl Drop for String {
    fn drop(&mut self) {
        // Vec 的 Drop：
        // 1. u8 没有 Drop glue，不需要逐元素析构
        // 2. 调用 GlobalAlloc::dealloc(ptr, layout)
        //    → 最终归还给 allocator (系统级: munmap / brk)
    }
}

栈上的 24 字节随栈帧弹出自动消失；堆上的 capacity 字节通过 dealloc 释放。 如果 String 被 move 给另一个变量，原变量的 ptr 置为 dangling（不会 double free）——这就是 Move 语义在内存层面的含义。
