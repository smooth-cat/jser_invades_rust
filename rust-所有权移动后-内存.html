源码

pub fn force_read() { let mut person = Person { name: "John".to_string(), // 堆分配 "John" age: 30, }; let person_raw_ptr = &person as *const Person; // 裸指针，记录栈地址 let mut person_2 = person; // ← Move！按位复制栈上的 (ptr, cap, len, age) person_2.name = "Tom".to_string(); // 旧 String "John" 被 drop → 堆释放 person_2.age = 1; unsafe { let old_person: Person = ptr::read(person_raw_ptr); // 从旧栈地址按位读出 println!("旧内存中的 person: {:?}", old_person); std::mem::forget(old_person); // 阻止析构 → 避免 double free } println!("person_2 {:?}", person_2); }

关键：person_raw_ptr 记录的是 栈地址 0x7fff_0000，不是堆地址。后面即使 person 被 move，这块栈内存的物理比特不会被清零——裸指针依然能读到残留值。

③ Move 移动：let mut person_2 = person

let mut person_2 = person; // Move 语义

Rust 的 move 在底层就是 memcpy：把 person 的 32 字节原样复制到 person_2 的栈空间。堆上的 "John" 没有任何变化，不会重新分配。

编译器在类型系统层面标记 person 为「已移动」，禁止后续安全代码访问它——但物理内存中的比特纹丝不动。

Move = 栈上 memcpy + 编译器层面「禁止旧变量再用」。堆数据零拷贝。这就是为什么 Rust 的 move 是零成本的——但旧栈地址上的比特仍然可读（unsafe 可绕过编译器限制）。

此刻 person 旧栈地址上的 name.ptr (0x5555_1000) 已经是悬垂指针——它指向的堆内存已被释放。如果后续通过 ptr::read 读出并让 Rust 正常 drop，就会对同一地址执行第二次 free → Double Free。

⑤ unsafe { ptr::read(person_raw_ptr) }

let old_person: Person = ptr::read(person_raw_ptr); // 等价于: 从栈地址 0x7fff_0000 起，按位复制 32 字节到 old_person

ptr::read 做的事和 move 一样——按位复制 (bitwise copy)。它从 person_raw_ptr 记录的旧栈地址读出 32 字节，构造出一个新的 Person 值。

问题是：读出的 name.ptr 仍然是 0x5555_1000（已释放的堆地址）！old_person 持有一个悬垂指针。

⑥ mem::forget(old_person)

println!("旧内存中的 person: {:?}", old_person); // 碰巧能读出 "John"（UB，但通常未被覆写） std::mem::forget(old_person); // 告诉 Rust：不要 drop 这个值

mem::forget 消耗 old_person 的所有权，但不调用析构函数。效果：old_person 的栈空间被回收，但不会执行 free(0x5555_1000)。

核心要点

Move 不清零旧栈内存：Rust 的 move 只是编译器层面的所有权转移 + 栈上 memcpy。旧地址的比特原封不动，只有 unsafe 的裸指针能绕过编译器读到它。
ptr::read 创造了一个「幽灵 owner」：old_person 和 person_2 的 name.ptr 曾指向同一块堆内存（在 Step 4 之前）。如果两者都 drop，就是 double free。mem::forget 是唯一的拆弹手段。
为什么 println! 能读出 "John"？：free 只是把内存还给分配器，不一定立刻覆写。在短时间内，旧数据大概率还在——但这是未定义行为 (UB)，绝不能依赖。
